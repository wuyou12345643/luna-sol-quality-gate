# Luna 执行与 Sol 验收

保留用户的整体目标，由主控负责拆分、集成与最终验收。优先使用个人 Agent `luna_worker`，其定义位于 `~/.codex/agents/luna-worker.toml`，模型为 `gpt-5.6-luna`，推理强度为 `max`。不修改现有模型配置、其他 Skill 或项目流程。

## 选择执行方式

- 简单或强顺序任务由主控直接完成；只有范围明确、边界清晰且可独立完成的部分才委派。调用本 Skill 是对本次任务内必要子代理协作的授权，不是创建独立侧栏聊天或外部操作的授权。
- 使用运行时实际提供的原生子代理接口。如果接口支持命名 Agent，选择 `luna_worker`，不得猜测未提供的参数。
- 若接口只支持模型与提示词，读取上述 TOML，将其指令和任务包传给子代理，显式设置 `gpt-5.6-luna`、`max`，并选择允许模型覆盖的最小上下文继承方式。明确这是等效委派，不是已加载命名 Agent。
- 若 Agent 文件缺失、原生委派不可用或目标模型被拒绝，报告具体限制，由主控继续可完成的工作；不静默替换模型，不借用独立聊天冒充子代理，不修改配置绕过问题。
- 核对当前主控实际模型，不根据角色名称推断。主控应为 Sol；本 Skill 不能切换当前会话模型。若无法确认或不是 Sol，说明情况，可以继续实现与检查，但最终标记“待 Sol 验收”，不能宣称 Sol 已验收。

## 委派契约

为每个 Worker 提供简短、完整的任务包：

```text
目标：本子任务需完成的具体结果。
输入：必要上下文、文件或资料。
范围：允许修改的文件/模块；范围外发现仅报告。
交付物：产物位置和必要说明。
验收标准：可观察的成功条件及适用检查。
边界：不更改总体目标，不扩大范围，不创建子代理或后台任务。
回报：实际变更、验证命令与结果、未验证项、阻塞及风险；交付待主控验收。
```

允许并行读取，写入任务分配互斥文件范围；共享文件由主控整合。遵循运行时并发限制。已有上游计划、文件所有权或验收标准时直接复用，不再生成一套互相冲突的流程。

## 主控质量门禁

Worker 完成后，主控读取实际文件、diff 或其他产物，不能只依据 Worker 的总结验收。核对需求覆盖、范围约束、无关内容保留情况与跨任务集成结果。

根据任务选择必要验证：代码执行相关测试及适用的构建/静态检查；研究核对关键来源与结论；文档检查内容和适用的渲染效果。复用项目已有标准，不为小改动机械添加测试，也不把无关检查当成阻塞项。

明确区分：

- 通过：主控有证据确认所有必要标准满足。
- 未通过：存在已确认缺陷或必要检查失败。给出具体返工要求，修复后复查受影响项目。
- 未验证：必要检查无法执行、证据缺失或 Sol 验收尚未发生。说明原因，不计为通过。

不要通过削弱测试、降低标准或隐藏失败来放行。相同阻塞反复出现且没有新证据时，停止重复派遣，由主控接管或报告需要的输入。任何必要门禁未通过时，不得宣称整体任务完成。

## 交付

简要说明产物、真实委派方式与模型、主控执行的检查、验收状态和残余限制。只有确认 Sol 主控完成上述检查，才能标记“Sol 验收通过”。这是指令层面的协作流程，不是 CI、权限控制或自动切换模型的机制。
